# First acceptance run on your own network

1. Close all previous ConnWatch instances before launching version 3.0. Use a fresh portable folder or the new setup shortcut.
2. Check that adapter detection shows the same private IPv4 and subnet mask as `ipconfig` on Windows. Choose the intended Wi-Fi/Ethernet adapter. A VPN or virtual adapter can lead to a different subnet.
3. Run Discovery first. Compare observed addresses with your router's client list, bearing in mind that router history, Wi-Fi isolation and sleeping clients affect visibility.
4. Run Standard on the same scope. Inspect one device's presence evidence and actual checked-port coverage. Review hostname/MAC/vendor as observations, not guaranteed product identity.
5. Give one address a friendly name, owner and truthful review note. Edit it again and inspect the annotation journal.
6. Safely change an expected service on a machine you own, then rescan. Inspect the change timeline. Do not turn off router/firewall protections merely to make discovery counts look complete.
7. Cancel a scan and confirm its partial address evidence remains with Cancelled status. It must not become a disappearance baseline.
8. Export PDF, CSV, HTML and JSON. Confirm the scope, time, selected ports, records and statuses match. JSON should contain no-response attempts as well as responding devices.
9. Close the app, reopen it through the EXE, and check history/annotations. A second launch should focus the existing network window where Windows allows it.
10. Keep reports private or redact device names and addresses before sharing.
